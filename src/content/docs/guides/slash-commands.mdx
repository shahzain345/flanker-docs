Choose a command in Discord’s slash menu, then fill in its named fields. Member, role, channel and attachment fields use Discord’s pickers. Numbers, choices and yes/no settings have their own controls. You do not need to paste a prefix command into a text field.

Commands are grouped by feature, with no numbered overflow menus. For example:

| Feature | Slash command |
| --- | --- |
| Message activity | `/messages` |
| Staff task progress | `/stafftasks` |
| Caption an image | `/media caption` |
| Quote supplied text | `/quote text:your words` |
| AFK across servers from a DM | `/afk reason:studying` |
| Translate text | `/server-tools translate text` |
| Ticket option transcript destination | `/ticket options set-log` |
| Family pets | `/family pets list` |
| Chess, including My Apps | `/games chess` |

Every public prefix command has a typed slash equivalent. Open a command in the [command reference](/commands/) to see its prefix syntax, mention syntax and links to the matching slash actions. Prefix aliases are also searchable below. For mention commands, mention Flanker and follow it with the same command and arguments you would use after your prefix.

Prefix reminders and command help use the current slash paths. For example, `,tr en bonjour` maps to `/server-tools translate text language:en text:bonjour`, and its mention version is `@Flanker translate en bonjour`. The `tr` alias is searchable below. Older `/utility` menus have been replaced by feature groups such as `/server-tools`.

To translate a specific message with slash commands, copy its text into `/server-tools translate text`. Discord does not pass reply targets to slash commands. Prefix and mention commands can translate a message you reply to; replying with just `,tr` defaults to English.

### Permissions and context

Slash and mention commands use the same feature handlers and permission checks as prefix commands. A slash command does not grant moderation access, bypass a disabled feature or skip an antinuke trust check. Discord can also restrict application-command access by server, role, channel or installation type.

**Profile installation only** filters to commands available through My Apps. Their availability still depends on Discord and the channel’s external-app settings. Account-linking and participant checks apply. The additional server-only `/confess` action opens a form.

### Differences when entering arguments

Slash commands have named fields rather than a free-form command line. Giveaway edits require their message target. Quote accepts either a readable message link or ID, or supplied text with an optional author picker. Discord does not pass the message you are replying to as slash-command context or grant private message-history access through My Apps. Media tools accept a file, source URL or member picker and otherwise use your avatar.

Some destinations accept a member, role or a clear/default choice. Discord shows those as separate optional fields. Supply the combination described in the reference; a clear or reset choice must be used on its own. Multi-role giveaway requirements can be changed through their dedicated edit actions.

Polls offer up to 10 typed answers and choose offers up to 25 typed choices. Larger free-form lists do not fit into a single native slash form. Discord limits an application to 100 global chat-input command names, 25 options per level, and one subcommand-group level. Flanker uses feature groups within those limits while keeping native typed fields. See [Discord’s application command documentation](https://docs.discord.com/developers/interactions/application-commands).

### Find a command

Search by slash path, prefix name, alias or field name. Links from the command reference open the matching action and show its fields.

## Limit a command to staff roles

Use `/commands rolecommands add` with the **role** field and a command name. For example, select your Moderators role and enter `ban` in **command-command**. The prefix equivalent is `,rc add @Moderators ban`; the mention equivalent is `@flanker rc add @Moderators ban`.

For a command with RC role rules:

- Members with any listed role may run it without its usual command permission.
- Everyone without a listed role is blocked, including administrators and Flanker Admins.
- Antinuke, protected members and roles, target hierarchy, channel visibility and Flanker's own permissions still apply. RC cannot grant security access or bypass an explicit owner requirement.
- Only the server owner can grant role-management commands through RC.

Rules cover the command root, its aliases and subcommands in that server. Use `/commands rolecommands list` or `,rc list` to review them. Removing the last role rule restores normal command access. Recovery commands such as `rc`, `help` and `access` stay available.

A **member** target has a different purpose: it blocks that member. It does not add them to the role allowlist. Existing member blocks and separate command/module switches still apply.
